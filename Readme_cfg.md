# Readme_cfg.md - Config設定

対象ファイル:
- `config/tudursvehiclemod.json`(クライアント設定)
- `config/tudursvehiclemod-server.json`(サーバー設定)

いずれもJSON形式で、ファイルが存在しない場合は初回起動時にデフォルト値で
自動生成されます。ゲーム内の設定画面から変更した場合は即座にファイルへ
保存されるため、手動でファイルを編集する必要は基本的にありません。

## ゲーム内での開き方

いずれかの車両に搭乗した状態で「乗り物メニューを開く」キーを押し、
乗り物メニュー内の「デバッグ」ボタンを押すと、デバッグメニューが開きます。
そこに「設定」(クライアント設定)と「サーバー設定」への入り口があります。

「サーバー設定」は、自分がホストしているワールド(シングルプレイ、または
自分が公開したLANゲーム)でのみ操作できます。リモートの専用サーバーの
設定は、この画面から直接変更することはできません。

## 1. 反映タイミングについて

設定項目によって、変更がいつ反映されるかが異なります。

- **即時反映**: 毎フレーム/毎tick読み直される設定。ボタンを押した瞬間から
  効果が変わります。
- **リロード時に反映**: リソースリロード(デバッグメニューのリロード
  ボタンで即座に実行可能)のタイミングで効果が変わる設定。テクスチャの
  読み込み処理に関わるものが該当します。
- **再起動が必要**: ゲームのそのセッション中、最初に一度だけ構築される
  仕組みに関わる設定。変更後、ゲームを再起動するまで見た目には反映
  されません。

以下の各項目でこの3種類のどれに該当するかを明記しています。

## 2. クライアント設定(`tudursvehiclemod.json`)

### 半透明処理(`translucencyMode`) - 再起動が必要

乗り物の透過部分(窓・光学系パーツ等)をどう描画するかの方式です。
デフォルトは`dither_texture`。

| 値 | 表示名 | 特徴 |
|---|---|---|
| `dither_shader` | ディザ (シェーダー) | このMOD独自のシェーダーでディザ処理。シェーダーパックとは併用できません(パックが独自の描画プログラムに置き換えてしまうため)。 |
| `dither_texture`(デフォルト) | ディザ (テクスチャ) | ディザパターンを読み込み時にテクスチャへ焼き込む方式。シェーダーパックと併用可能で、水面やエンティティとの前後関係も正しく処理されます。 |
| `translucent` | アルファブレンド | バニラの半透明パイプラインをそのまま使用する、素直なアルファブレンド。シェーダーパックと併用可能ですが、描画順に依存するため水面が透過部分の奥に隠れてしまう場合があります。 |

### サーチライト(`searchLightMode`) - 照明は即時反映、形状は再起動が必要な場合あり

サーチライトの照明方式と見た目の形状の両方を1つの設定で切り替えます。
デフォルトは`beam`。

| 値 | 表示名 | 特徴 |
|---|---|---|
| `beam`(デフォルト) | ビーム | 閉じた半透明の円錐(MCヘリ本来の形状)。エンティティのみを照らします。 |
| `dynamic_light` | ダイナミックライト(実験的) | 見た目はビームと同じですが、地形も実際に再照明されます(チャンクの再構築を伴う実験的機能)。 |
| `blades` | 光条 | ビームと同じ照明方式のまま、円周方向に伸びる数本の光条として描画。どの半透明処理設定でも正しく表示されます。 |
| `bands` | バンド | ビームと同じ照明方式のまま、長さ方向に並ぶ環状のリングとして描画。 |
| `dashes` | ダッシュ | 光条をさらに短い区間に区切った、破線状の表示。 |

### サーチライトの明るさ(`searchLightBrightness`) - 即時反映

- 範囲: 0 - 6(初期値: 3.0、0.5刻み。3.0を超えると1.0刻み)
- 点灯中のサーチライトがブロックやエンティティを照らす明るさの倍率です。
  各ライトに設定された強度を置き換えるのではなく、それを倍率で調整します。
  0にすると照明が無効になり、見た目のビームのみが残ります。

### ブロック描画の明るさ(`searchLightBlockBrightness`) - 即時反映

- 範囲: 0 - 3(初期値: 1.0、0.5刻み)
- サーチライトが地形を染める強さです。サーチライトの明るさ(エンティティ
  照明を制御)とは独立しています。0にすると地形への描画のみが無効になり、
  エンティティ照明はそのまま残ります。

### ブロック描画のサンプル数(`searchLightBlockOverlaySampleCount`) - 即時反映

- 範囲: 50 - 400(初期値: 200、50刻み)
- 地形のどこが照らされているかを判定するために、サーチライトが1tick
  あたりに発射するサンプル数です。ライトの形状や射程とは無関係の固定値
  です。少ないほど軽くなり、サンプルが粗いことで生じる隣接面のわずかな
  隙間は拡散処理が補完します。

### ブロック描画の更新間隔(`searchLightBlockOverlayIntervalTicks`) - 即時反映

- 範囲: 1 - 10 tick(初期値: 4)
- 地形への描画を完全に再計算する頻度です。サーチライトの処理の中で最も
  多くの一時メモリを消費する部分のため、値を大きくするとメモリの消費が
  比例して減ります。その代わり、素早く動くビームに対して描画の追従が
  わずかに遅れます。照明そのものは、この設定に関わらず常に毎tick更新
  されます。

### 円錐表示距離(`searchLightConeDisplayDistance`) - 即時反映

- 範囲: 0.1 - 1.0(初期値: 1.0、0.1刻み)
- 円錐/光条/バンド/ダッシュの見た目の形状が届く距離を、ライト本来の
  長さに対する割合で指定します。描画される範囲のみに影響し、照明や
  ブロック描画の範囲は変わりません。

### チャンク再構築間隔(`searchLightChunkRebuildIntervalTicks`) - 即時反映

- 範囲: 1 - 40 tick(初期値: 10)
- サーチライトが「ダイナミックライト」の場合のみ使用されます。ビームの
  移動に応じて地形の再照明を要求する頻度です。小さいほど滑らかですが
  負荷が増えます。

### リング数の倍率(`searchLightRingCountMultiplier`) - 即時反映

- 設定画面では0.5・1.0・2.0・3.0の間を循環(初期値: 1.0)
- 光条/バンド/ダッシュのビームが長さ方向に生成するリング数の倍率です。
  サイズに応じた自動調整に加えて適用されます。上限は設けられていない
  ため、画面上の循環範囲を超える値を使いたい場合はファイルを直接編集
  してください。

### ブレード数の倍率(`searchLightBladeCountMultiplier`) - 即時反映

- 設定画面では0.5・1.0・2.0・3.0の間を循環(初期値: 1.0)
- 光条/ダッシュのビームが円周方向に生成するブレード数の倍率です。
  リング数の倍率と同様、上限はなくファイルの直接編集で超過値を指定
  できます。

### ディザ拡大率(`translucencyDitherUpscale`) - リロード時に反映

- 取りうる値: 0.25 / 0.5 / 1 / 2 / 4 / 8(初期値: 4.0)
- ディザ処理前のテクスチャ拡大率です。1より大きいとメモリと引き換えに
  細かい模様になり、1より小さいと縮小してメモリを節約します。半透明処理
  が「ディザ (テクスチャ)」の場合のみ意味を持ちます。

### GPUテクスチャ圧縮 (BC1)(`translucencyDitherGpuCompression`) - リロード時に反映

- 初期値: `false`
- ディザ処理したテクスチャをBC1で保持し、VRAM使用量を1/8にします。
  アルファは正確に保たれますが、色の細部は近似になります。Minecraft
  本来のテクスチャAPIの外で動作するため、失敗時は自動的に従来方式へ
  戻ります。半透明処理が「ディザ (テクスチャ)」の場合のみ意味を持ちます。

### ディザ最大テクスチャ(`translucencyDitherMaxTextureSize`) - リロード時に反映

- 範囲: 512 - 8192 px(初期値: 2048、倍々で循環)
- 拡大後テクスチャのサイズ上限です。ディザ拡大率を制限します。半透明
  処理が「ディザ (テクスチャ)」の場合のみ意味を持ちます。

### 実験的な三角形描画(`experimentalTriangleRendering`) - 再起動が必要

- 初期値: `false`
- 三角形あたり4頂点ではなく3頂点で送信する実験的な描画方式です。半透明
  処理が「ディザ (シェーダー)」の場合のみ意味を持ちます。

### 描画距離に合わせる(`matchChunkViewDistanceForEntityRender`) - 即時反映

- 初期値: `true`
- このMODのエンティティ(車両・弾丸)に、短いエンティティ描画距離では
  なくゲーム本来の描画距離(チャンク表示距離)を使用します。

### 描画カリングを無効化(`disableEntityRenderCulling`) - 即時反映

- 初期値: `true`
- このレンダラー独自の距離・視錐台判定を省略し、読み込まれている限り
  常に車両を描画します。

### 三人称HUD(`showHudInThirdPerson`) - 即時反映

- 初期値: `true`
- 三人称視点でも乗り物HUDを描画するかどうかです。一人称視点では、この
  設定に関わらず常に描画されます。

### 航空機カメラの最大距離(`maxAircraftCameraDistance`) - 即時反映

- 範囲: 20 - 160ブロック(初期値: 80、20刻み)
- 飛行中に三人称カメラをどこまでズームアウトできるかです。

## 3. サーバー設定(`tudursvehiclemod-server.json`)

「サーバー設定」画面の変更は再起動不要で即座に反映されます。

### 並列ヒット検出(`parallelHitDetectionAcrossVehicles`) - 即時反映

- 初期値: `false`
- このMOD独自のヒット検出処理を、各車両が個別のtick内でインライン実行
  する代わりに、全車両分をまとめて1tickにつき1回の並列処理としてバッチ
  実行します。ヒット検出が明らかにボトルネックとなっている、高ポリゴン
  車両が多いワールドでオンにしてください。

### 並列ヒット検出の最小車両数(`parallelHitDetectionMinimumVehicles`) - 即時反映

- 範囲: 1 - 20(初期値: 3)
- そのtickでヒット検出を必要とする車両が何台以上であれば、上記の並列
  処理を使う価値があるかを指定します。「並列ヒット検出」がオンの場合
  のみ意味を持ちます。

### 破壊された車両のデスポーン(`destroyedVehicleDespawnEnabled`) - 即時反映

- 初期値: `true`
- 破壊された車両が、残骸として永久にワールドに残り続ける代わりに、
  下記のタイマー経過後に自動的にデスポーンするようになります。正常に
  運転可能な車両には一切影響しません。

### 破壊された車両のデスポーンまでの時間(`destroyedVehicleDespawnSeconds`) - 即時反映

- 範囲: 30 - 1800秒(初期値: 300 = 5分)
- 破壊された車両がデスポーンするまでワールドに留まる時間です。「破壊
  された車両のデスポーン」がオンの場合のみ意味を持ちます。

### 空母滑走路の想定幅(`carrierRunwayExpectedWidth`) - 即時反映(新規生成される滑走路タイルのみ)

- 範囲: 10 - 60ブロック(初期値: 30.0)
- 実際の車両ファイルの滑走路幅がまだ分からない、MOD読み込み時点で空母
  滑走路の支持タイルのサイズを決めるために使う想定幅です。実際の滑走路
  幅がデフォルト値と異なる場合は、実際の値に合わせて設定してください。
  既存のタイルは既に固定されたサイズを維持するため、変更は新しく生成
  されるタイルにのみ影響します。

### 弾丸チャンクロード上限(`projectileForcedChunkLimit`) - 即時反映

- 取りうる値: 無効(0) / 50 - 1000(初期値: 300)
- 飛翔中の弾丸がサーバー全体で強制ロードするチャンク数の合計上限を
  設定します。これにより、プレイヤーから離れた場所を飛ぶ弾丸でも着弾
  まで動作し続けます。上限を超える場合、召喚タイミングが最も古い弾丸
  から解除されます。無効(0)にすると、弾丸は一切チャンクを強制ロード
  しなくなります。CAS/Carrier機体や他の常時ロード機能には影響しません
  (それらは対応する武器・車両ファイル側で調整できます)。

## 4. 設定画面には出てこない項目

以下は設定ファイルには存在しますが、ゲーム内の設定画面には表示されて
いないため、変更するにはファイルを直接編集する必要があります。

### `searchLightBlockOverlayRange`(クライアント設定)

- 初期値: `50.0`(ブロック)
- サーチライトから何ブロックの範囲まで地形をその色で染めるかです。
  この距離に向かって効果が徐々に薄れていきます(唐突に途切れることは
  ありません)。ライト自体の長さがこれより短い場合は、ライトの長さで
  打ち切られます。この項目はブロック数の3乗に比例して負荷が増えるため、
  この機能全体の中で最も負荷に影響する設定です。低スペック環境では
  下げ、逆に余裕がある場合は上げてください。

### `worldDataCleanupChunksPerTick`(サーバー設定)

- 初期値: `-1`(件数上限なし)
- `/tvm clean -d`(ワールド上の全ての未読み込みチャンクを含めて車両を
  完全削除するコマンド)が、1tickあたりに調査するチャンク候補数の上限
  です。-1(デフォルト)では件数による上限を設けませんが、これは
  「1tickで処理が完結する」という意味ではありません。処理時間そのもの
  は常に別途制限されており、進捗も定期的にログへ出力されます。正の値
  (例: 50)を設定すると、その時間制限に加えてチャンク数でも上限を
  設け、1tickあたりの負荷をより穏やかにする代わりに、処理全体の完了
  までの時間を延ばすことができます。
