item.DroneControlStickItem           ← 機体へ右クリックしてUUIDを登録するスティック(UAV/

block.DroneCenterBlockEntity         ← TargetDroneの自律AI飛行制御ブロック(円軌道/ウェイポイント

### なぜ「乗り物ごとに新しいItem/EntityTypeを作らない」のか

バニラの仕組み上、**ItemやEntityTypeなどのレジストリはMod初期化時(ワールド/データパック読み込みより前)に確定してしまう**ため、データパックで後から追加した乗り物のために新しいItemクラスを動的に登録することはできません。
そのためこのMODは:

- **EntityTypeは「操縦方法の種類」ごとに1つ**(ヘリ・車・船・潜水艦・航空機)。見た目が違う乗り物は
  同じEntityTypeに別の`VehicleDefinition`を割り当てるだけ。
- **Itemも「種類×Tier」の25種類だけ**(車Tier1〜5、船Tier1〜5、…)。どの`VehicleDefinition`を
  実際にスポーンするかは、アイテムを使った時に開く選択画面でプレイヤー自身が選ぶ。

という設計にしています。

### 新しい乗り物を「コードなし」で追加する

見た目だけ違う乗り物(操縦感覚は既存のいずれかと同じでよい場合)は、コード変更ゼロで追加できます。

1. Blenderなどで `.obj` をエクスポート → `assets/tudursvehiclemod/models/obj/my_vehicle.obj`
2. テクスチャを `assets/tudursvehiclemod/textures/vehicle/my_vehicle.png`
3. 定義を `data/tudursvehiclemod/vehicles/my_vehicle.json` に追加(既存のjsonをコピペして値を変えるだけ)。`entity_type` には既存のいずれか(`tudursvehiclemod:car`, `helicopter`, `ship`, `submarine`, `aircraft`)を指定
4. (任意)`weapons` に武装を追加、`spawn_item`に表示名とTierを追加すれば、対応する種類のTier式スポーンアイテムの選択画面に出るようになる(次項)
5. (任意)`is_uav`/`is_target_drone`(いずれもtrue/false)を設定すると、通常の搭乗が無効化され、無人機(UAV)・自律ドローン(TargetDrone)としてのみ運用できるようになります。詳細は後述の「無人機(UAV)・自律ドローン・近接航空支援(CAS)」セクションを参照してください
6. (任意、乗り物の種類を問わず設定可能)`runway`を設定すると、その乗り物へ空母(Carrier)の滑走路(艦載機の発艦・着艦・停泊が可能な甲板)を持たせられます。詳細は後述の「空母(Carrier)システム」セクションを参照してください。より単純に、乗ることのできる甲板として使用することも可能です。

**操縦ロジック自体を変えたい**場合だけ、`AbstractVehicleEntity` を継承した新しいJavaクラス(`updateVehicleMovement`の実装)が必要です。本体modを拡張する代わりににアドオンModで追加することも可能です。

### 武装を追加する

`weapons` はリストなので、1つの乗り物に複数の武装を載せられます:

```json
"weapons": [
  {
    "seat_index": 1,
    "offset_x": 0.0, "offset_y": 0.5, "offset_z": 0.6,
    "projectile_item": "minecraft:iron_nugget",
    "damage": 4.0,
    "velocity": 3.0,
    "cooldown_ticks": 5
  }
]
```

- `seat_index`: この武装を撃てるのは、その座席番号(`seats`配列のインデックス、0始まり)に乗っている乗客だけ
- `projectile_item`: 弾として飛ばす**既存のアイテムID**。バニラの投げたアイテムの描画をそのまま使う
- 発射は既定でRキー(`key.tudursvehiclemod.fire_weapon`)。現状は武装インデックス0番を撃つ決め打ちの簡易実装
- サーバー側で「本当にその座席に乗っているか」「クールダウン中でないか」を再検証してから発射する

### スポーンアイテム(Tier式)

乗り物の**種類ごと**(車・船・潜水艦・航空機・ヘリコプターの5種類)に、Tier1〜5のスポーンアイテムが最初から用意されています(計25種類、`ModItems.TIERED_SPAWNERS`)。アイコンは種類ごとに固定(MOD本体に同梱、リソースパック不要)です。

**使い方**: 対応する種類・Tierのスポーンアイテムを持った状態で右クリックすると選択画面が開きます。
選ぶとその場でスポーンし、アイテムを1つ消費します(クリエイティブモードでは消費されません)。
乗り物を**しまう**(誰も乗っていない状態でスニーク+右クリック)と、対応するスポーンアイテムが1つ手元に返ってきます。クリエイティブモードでは複製を防ぐためアイテムを渡さずそのまま消滅します。

- 乗り物側で設定するのは`spawn_item.tier`(1〜5、省略時1)と`display_name`だけです
- Tierごとのアイコンは外周の縁取りで視覚的に区別されます(Tier2=緑角括弧、Tier3=青全周枠、Tier4=紫全周枠+白点、Tier5=金太枠+白点)

### 操縦方式(スロットル式 + 視点追従)

- **W/S = スロットル**: クルーズコントロール方式。W/Sでスロットル値を上下させ、離すとその値を維持。実際の速度はスロットル値 × `max_speed`へ毎ティックなめらかに近づきます
- **車・船**: 視点操作は一切機体に反映されません(常にフリールック相当)。A/Dで左右に旋回します。
- **航空機**: 機首の向き(ヨー+ピッチ)は操縦者の視点の向きに追従します。A/Dは見た目のバンク(傾き)になります。
- **ヘリ**: 機首の向き(ヨー+ピッチ)は操縦者の視点の向きに追従します。通常時はW/A/S/D入力で前後左右に動きます。マニュアルモードでは視点の動きに機体姿勢が連動します。
- **潜水艦**: 視点操作は一切機体に反映されません(常にフリールック相当)。A/Dで左右に旋回します。潜航操作など詳細は後述の専用セクション参照。
- **車両のしまい方**: 誰も乗っていない状態でスニーク+右クリックで回収できます。Mobなどが搭乗している場合はパイロット席より強制降車(専用キー長押し)を行ってください。
- **HUD表示**: 何も設定がない場合はスロットル値を示すバーと燃料残量を示すバーのみが表示されます。完全に表示を消したい場合は空のHUD設定ファイルを割り当ててください。

### クリエイティブタブ

`ModItemGroups`が専用タブを登録します。中身は`VehicleRegistry`から動的に列挙されるため、データパックでの乗り物の追加/削除や`/reload`にも自動的に追従します。

### OBJモデルの制約

`ObjModel`/`ObjModelLoader`は`v`/`vt`/`vn`/`f`のみ対応(n角形はファン三角形分割)。
`.mtl`/`usemtl`は無視 — テクスチャは1乗り物1枚(JSON側の`texture`フィールド)固定です。
グループ分け(`spinning_parts`/`toggle_parts`用)は`o`/`g`どちらの宣言にも対応しています。

## 航空機(AircraftEntity)の現在の実装

### 姿勢管理: クォータニオン方式

ヨー・ピッチ・ロールを別々のEuler角として管理するのではなく、単一の`Quaternionf orientation`フィールドで一元管理しています。入力は「現在の姿勢に対する増分回転」として適用され
(`orientation.mul(delta).normalize()`)、ヨー/ピッチ/ロールの数値が必要な場面(カメラ・座席・回転パーツなど)でのみ、都度Euler角へ変換して取り出します(`extractYawPitchRoll`)。

この方式により、バニラの視点操作(±90度でクランプされる)を一切経由しない独自の視点入力パイプライン(`PlayerLookRateMixin`でマウスの生の移動量を捕捉→`AircraftOrientationInputPayload`でサーバーへ送信)と組み合わせて、**ループ(宙返り)が制限なく可能**になっています。

### 飛行物理

- **地上/水上(surfaced)**: ヨーのみ視点に追従、ピッチ・ロールは`OnGroundPitch`(後述)へ向けて固定。スロットル操作で加減速しますが、**減速側は加速側よりゆっくり効きます**
  (以前の設定の半分の速さ。加速や空中での挙動には影響しません)
- **通常飛行(スロットル50%以上)**: ヨー・ピッチとも視点に追従、A/Dでロール(360度バレルロール可)。速度はスロットル×`max_speed`へなめらかに追従
- **滑空(スロットル50%未満、空中)**: 速度に応じて重力が段階的に強まる(完全に速度を失うと通常の落下と同じ重力の6倍)
- **着陸装置(ギア)展開中**: 最高速度が70%に低下(空気抵抗を表現)
- **減速(空中飛行時、スロットルを下げた時)**: 加速時より1.5倍速く効きます
  (地上でのブレーキは上記の通り別途設定されています)

### 無人時(パイロットがいない場合)の挙動

- 有人時と**同じ物理演算**(地上/通常飛行/滑空の判定・処理)を通ります。専用の別処理はありません
- スロットルが毎ティック少しずつ弱まっていきます(0.01/tick、フルスロットルから0まで約5秒)
- 姿勢は、猶予期間なしで常に水平飛行(現在の進行方向のまま、ピッチ0・ロール0)へ緩やかに近づきます
- クライアント側では独自に位置・速度を計算し直さず、サーバー側の計算結果(同期される速度)をそのまま使って`move()`するだけにしてあります。これはサーバー・クライアントそれぞれが独立に計算すると、値がズレて同期のたびに「補正されてカクつく」ため

### `OnGroundPitch`(地上姿勢)

地上/水上にいて、かつ**十分に減速している(最高速度の15%以下)**間、指定した角度(度)へ向けてピッチを合わせます(有人・無人問わず動作)。
着陸直後、まだ速度が残っているロールアウト中は、着地した瞬間の姿勢をそのまま保ち、減速し切ってから地上姿勢へ移行します。目標のヨーは、この移行が始まった瞬間の値を一度だけ固定して使います(毎ティック再計算すると、SLERP(球面線形補間)の性質上ヨーが意図せずドリフトし、不安定になるため)。

逆に、離陸のため加速中で**最高速度の15%以上**(地上姿勢のしきい値と統一)に達すると、機体を水平(ピッチ・ロールとも0)へ姿勢を合わせます。地上姿勢(尾輪式などで機首上げのことが多い)のまま滑走を続けるのではなく、離陸に向けて姿勢を整える形です。

地上での加速性能は、この姿勢制御が離陸前に間に合うよう、通常の半分の速さにしています。

**姿勢の同期について**: ヨー・ピッチ・ロールは、バニラ標準の同期の仕組み(`super.setYaw`/`getYaw`など)に頼らず、専用の同期フィールド(DataTracker)で明示的に同期しています。調査の結果、バニラ標準の同期は、**位置が変化していない間は回転の同期を送らない**という最適化を行っているらしく、地上で静止した機体のピッチが着陸時の姿勢のまま固まって見える、という不具合の原因になっていました。スロットル・ギア状態などの同期に使っているDataTrackerの仕組みは位置の変化と無関係に同期されるため、この問題を避けられます。

### 失速

飛行中(非接地時)、実際の速度が最高速度の20%を下回ると失速状態になり、パイロットの操作や無人時の水平飛行補正よりも優先して機首を強制的に真下へ向けます。最高速度の30%まで回復すると解除されます(発動20%・解除30%とヒステリシス(発動と解除のしきい値を変える仕組み)を持たせることで、しきい値付近での頻繁な切り替わりを防止)。

### 急降下加速・上昇時の減速

- 上昇(機首上げ)・降下(機首下げ)は単一の連続式で処理し、ピッチ0度を境にブランチが切り替わる不具合(降下45度付近での速度低下、上昇減速が効かないケース)を解消
- **降下**: 機首下向き角度に連動して連続的に速度目標が上がる(垂直降下で最高速度の1.5倍)
- **上昇**: 機首上向き角度に連動して連続的に速度目標が下がる(垂直上昇で0)
- **離陸可能・滑空状態の判定**: 実際の速度が最高速度の何%かで判定

### マニュアルモード

トリガーキー(既定M、長押し1秒でトグル)で、水平飛行への自動補正(無操作5秒後の自動水平化)を完全に無効化できます。HUDに状態表示。

### 速度表示

HUDに実際の速度をkb/h(1kb=1,000ブロック)で表示。

### HUD表示

デフォルトでは、スロットルバー・速度(kb/h)・FREE LOOK/MANUAL MODE表示のみの
簡易HUDです。

**MCヘリ互換のHUDスクリプト機能**に対応しています。MCヘリのHUD設定ファイル仕様に準拠したテキスト形式のHUDスクリプトを、コード変更なしでそのまま(またはほぼそのまま)読み込んで描画できます。

- 配置場所: `assets/<namespace>/hud/<name>.txt`(このMODの名前空間に限らず、リソースパックや他MODの名前空間からも読み込みます)
- 参照するテクスチャ: `assets/tudursvehiclemod/textures/gui/<name>.png`(256x256推奨)に配置してください
- 乗り物のJSON定義ファイルに`"hud": "<スクリプト名>"`を追加すると、そのスクリプトが使用されます(MCヘリ本家と同じく、機体ごとの設定でHUDファイルを指定する方式)。未指定、またはスクリプトが見つからない場合は簡易HUDにフォールバックします
  (`aircraft.json`には`"hud": "plane"`、`helicopter.json`には`"hud": "heli"`を既定で設定済み)
- テクスチャは、スクリプトと同じ名前空間に限らず、読み込まれている全ての名前空間から名前(拡張子なし)で検索します(例: 移植データが`mcheli`名前空間のままでも動作します)
- 対応済み: `Call`/`Exit`/`If`~`EndIf`(入れ子非対応、本家同様)/`Color`/`DrawString`/`DrawCenteredString`/`DrawTexture`/`DrawRect`/`DrawLine`/`DrawLineStipple`(破線は簡略化し実線描画)/`DrawGraduationYaw`/`DrawGraduationPitch1`/`DrawGraduationPitch2`/`DrawCameraRot`。式(四則演算・比較・論理演算・三項演算子・16進数)や変数参照にも対応
- 未対応: `DrawEntityRadar`/`DrawEnemyRadar`(このMODにレーダー装備の概念がないため、読み込みはするが描画は何もしない扱い)
- 変数: 本家の変数一覧(`yaw`/`pitch`/`roll`/`throttle`/`pos_x`など)にほぼ対応。このMODに該当概念がないもの(レーダー等)は安全な既定値を返します。独自拡張として`manual_mode`(マニュアルモード中か)・`stalling`(失速中か)・`gear_deployed`(ギア展開中か)・`speed`(実速度、ブロック/tick)・`speed_kbh`(同、kb/h)変数も追加しています
- `stick_x`/`stick_y`: 航空機はロール入力(A/D、保持状態なので安定)とマウスのピッチ入力(保持状態ではなく毎ティック消費されるため、値が瞬間的になります)。それ以外の乗り物は横方向・前後方向の入力を使用します
- テクスチャは実際のPNGファイルの寸法を読み取って正しくUV座標を計算します
- リソースリロード(F3+T等)で再読み込みされます

### ランディングギア

- **自動展開**: 着陸した瞬間に自動展開します。自動収納はしません(手動のみ)
- **手動格納/展開**: Gキー(既定、`key.tudursvehiclemod.gear_toggle`)。次に実際に着陸すると自動展開が上書きします
- 展開中は最高速度が低下します(前述)

### ハッチ・キャノピー

Hキー(既定、`key.tudursvehiclemod.hatch_toggle`)で開閉するトグルパーツに対応しています(回転式・スライド式の両方)。1回のキー操作でハッチ・キャノピーの両方が同じ状態(開/閉)に切り替わります。

- 召喚直後は、ハッチは閉じた状態です(キャノピーは開いた状態)
- 搭乗時、ハッチは搭乗前の状態を維持します(自動では開閉しません)。キャノピーは搭乗時に自動で格納(閉)されます

### 三人称視点でのプレイヤーモデル連動

搭乗中のプレイヤーモデル(三人称視点で見える自分の姿、または他プレイヤーから見た搭乗者の姿)が、**機体のパーツの一部として**機体の姿勢に完全に連動します(体全体が機体のヨー・ピッチ・ロールと一致)。

**頭のヨー(左右)方向は、フリールック中でない限り機体の向きに固定されます。ピッチ(上下)方向は現在もバニラ本来の挙動(プレイヤー自身の視点方向に応じて独立して動く)のままです。**

実装は`LivingEntityRenderer`へのMixin3点(`AircraftRidingRenderState`インターフェース、`LivingEntityRenderStateMixin`、`LivingEntityRendererMixin`)です。`setupTransforms`メソッド(バニラがボディヨー回転を行列スタックへ適用する専用メソッド)の`bodyYaw`引数自体を機体のヨー角へ差し替え、その直後にピッチ・ロールぶんの回転を追加で乗算しています。

### カメラ

- 通常時: 機体の向きに完全に追従するカメラ(コックピット視点、傾きも反映)
- フリールック中: プレイヤー自身の視点操作がそのまま反映され、機体の向きには影響されません
  (三人称の場合、バニラ自身の現在のカメラ回転に沿ってズーム距離ぶん引いた位置になります)
- 三人称ズーム: PgUp/PgDn(既定)で4ブロック単位、地形との衝突判定つき
- 三人称の対面視点(F5を2回押す、バニラの2段階目の三人称視点)にも対応しています

## 潜水艦(SubmarineEntity)の現在の実装

マウス操作を一切機体操作に反映しない、完全キー操作の乗り物です。視点は常に(航空機のフリールックと同様に)自由に動かせます。

### 水上/潜航の切り替え

Hキー(既定、ハッチ/キャノピー用のキーと共用)で切り替えます。この状態はハッチ系トグルパーツ(`toggle_parts`の`trigger: "key"`)の開閉状態と共通で、潜航に入るとハッチが閉じ、浮上するとハッチが開きます。スポーン直後は水上航行モード(ハッチ開)です。

### 水上航行モード

艦船(ShipEntity)と全く同じ操縦感覚(スロットル+A/Dによる直接ヨー旋回)ですが、以下の点が異なります。

- **旋回時の傾き**: 艦船と逆になります。艦船は重心が水面より上にあるため遠心力で外向きに傾きますが、潜水艦は重心が水面より下にあるため内向きに傾きます

潜航中は`AddPartWeapon`等の武器パーツの照準連動が停止し(向きが固定されます)、武器の発射自体もできなくなります。潜航中も使用できるのは魚雷(`Type=Torpedo`)のみですが、武器設定ファイルに`UsableWhileDiving = true`を指定すれば、他の
武器タイプも潜航中に使用可能にできます。使用不可な武器を選択している間は、`weapon_bay`トリガーの武器倉パーツも(選択されていても)開きません。

### 潜航モード

- **W/S**: スロットル(水上航行モードと共通、後述の制限あり)
- **A/D**: 進路変更(水上航行モードと共通、直接ヨー旋回)
- **Space**: 機首上げ(浮上方向にピッチ変化)
- **左Ctrl(既定、降下キーと共用)**: 機首下げ(沈降方向にピッチ変化)
- **十字キー上**: 姿勢を変えずにそのまま上昇
- **十字キー下**: 姿勢を変えずにそのまま下降

航空機と同様、無操作が一定時間(5秒)続くとピッチが水平(0度)へ自動的に戻ります。マニュアルモード(Mキー長押し、航空機と共通)でこの自動水平化を無効化できます。潜航中はロールは常に0へ戻ります(水中でのバンクはありません)。

機首上げ状態のまま水面に到達すると、航空機の失速よりも緩やかに機首が水平方向へ戻り、その間はやや強めの下向きの力が加わります(浮上し続けてしまうのを防ぐため)。

水中にいる間、操作(スロットル・ピッチ・十字キー)以外の要因では一切上下移動しません(重力・浮力は完全に無効化しています)。水から完全に出た場合(座礁など)のみ、通常の重力が働きます。

### スロットルの制限

通常は前進は100%まで、後進は-20%までに制限されています。プラスとマイナスを直接切り替えることはできず(スロットル0%にしたい場合に調整しやすいように)、0%の状態で待機してから逆方向に加速し始めます。

### 無人時の挙動

パイロットがいない場合も、スロットルが自然と0%へ戻っていく点を除いて有人時と全く同じ処理を通ります(専用の別処理はありません)。

### カメラ・プレイヤー表示

視点(ヨー・ピッチ)は常にプレイヤー自身の操作がそのまま反映されます(フリールック相当)が、ロール(傾き)だけは機体自身のものがカメラ・三人称プレイヤー表示の両方に反映されます(航空機のフリールック時と同じ仕組みを共有しています)。

## 無人機(UAV)・自律ドローン・近接航空支援(CAS)

プレイヤーが直接搭乗しない形で乗り物を運用する、3つの独立した仕組みです。

### UAV(無人航空機、遠隔操縦ステーション)

機体JSON定義に`"is_uav": true`を設定すると、その機体は通常の搭乗(座席への直接乗車)ができなくなります。代わりに以下の手順で遠隔操縦します:

1. **Drone Control Stick(登録スティック)**を持って対象の機体に右クリックすると、そのスティックへ機体のUUIDが登録されます(1本のスティックは常に直近登録した1機のみを保持し、再登録すると上書きされます)
2. **UAV Station(ステーションブロック)**へ登録済みスティックを挿入すると、そのステーションがその機体に紐付けられます
3. ステーションを右クリックすると、プレイヤーはその機体へ遠隔操縦として搭乗します。視点入力・武器発射も含め、通常の搭乗と全く同じ操作感覚で操縦できます
4. 機体が読み込み範囲外にある場合、ステーションは最後に確認した座標のチャンクを一時的に強制読み込みし(最大5秒)、機体を探索します

### 標的ドローン(TargetDrone、自律AI飛行)

機体JSON定義に`"is_target_drone": true`を設定すると、同様に通常の搭乗ができなくなります。UAVと全く同じ登録スティックの仕組みを使い、**Drone Center(ブロック)**へスティックを挿入して紐付ける点も共通ですが、Drone Centerが有効化している間、機体はプレイヤーの操作なしに自律AIで飛行します。

- **円軌道モード(デフォルト)**: ウェイポイントが未設定の場合、Drone Centerの上空を指定高度で円軌道飛行します。旋回半径は機体自身の性能(旋回速度・巡航速度)から自然に導出されます(固定値ではありません)
- **ウェイポイント巡回モード**: Drone Centerの設定画面から複数のウェイポイントを直接入力するか、**Drone Route Book**(アイテム)を挿入することで、そのルートを巡回飛行します
- **Drone Route Book**: オフハンドに持って実際に機体で飛行しながらJキーでウェイポイントの記録を開始・終了できる、実地飛行によるルート記録用アイテムです
- **Home Point**: 着陸目標地点です。デフォルトはスティック紐付け時の機体位置で、他のウェイポイントと同様に編集可能です
- 設定画面から有効化・無効化を切り替えられます。飛行中に無効化すると、その場で操作を失うのではなく、Home Point付近へ安全に着陸してから停止します
- Drone Centerも、機体が読み込み範囲外に出ないよう、機体の現在位置を中心とした3x3チャンクを常時強制読み込みします

### 近接航空支援(CAS、`WeaponType.CAS`)

母艦・地上車両等に搭載する武器の設定ファイル(`.txt`)で武器種別を`CAS`にすると、その武器は実弾を発射する代わりに、支援機(別の乗り物定義)をその場でスポーンさせ、設定されたウェイポイントルートを自動飛行させながら攻撃させます。

- 発射すると、クロスヘアの照準先(地上の目標地点)がルートの基準座標としてマークされます
- 設定された支援機がルートの最初のウェイポイント位置にスポーンし、ルートを自動飛行します
- `attack=true`が設定されたウェイポイントを通過している間、指定した武器スロットで自動的に射撃します
- 最後のウェイポイントに到達すると消滅します(空母(Carrier)の艦載機とは異なり、帰投・着陸はしません)
- 生存期間のタイムアウト・一定時間進行がないまま停滞した場合のタイムアウトという、2種類の安全装置を持ちます

これらの仕組みは、後述の空母(Carrier)システムとも共通の基盤(ウェイポイント巡回・攻撃判定・チャンク強制読み込み)を土台としています。

## 空母(Carrier)システム

乗り物を空母として機能させ、艦載機の発艦・自動飛行・帰投を管理する機能です。**特定の乗り物タイプに限定した機能ではありません。** 実装上も`entity_type`への依存は一切なく、艦船に限らずどの乗り物にも設定できます。「空中空母」のような架空の航空機に艦載機を発艦させることも、以下の項目だけで実現できます。

### 滑走路(`runway`/`runways`)

**滑走路(`runways`)と、後述する艦載機発艦武器(`Type = CARRIER`)は互いに必須の関係ではなく、それぞれ単独でも利用できます。** 武器を持たず甲板としてのみ滑走路を設定することも、逆に`Type = CARRIER`の武器だけを設定し滑走路は定義しない(発艦した機体を別の手段で回収する前提とする)こともできます。両方を組み合わせて「発艦させた艦載機が実際にこの滑走路へ着艦して回収される」という一連の動作にすることも可能で、これは空母の基本形として元々意図されている組み合わせです(詳細は後述の「艦載機発艦武器との組み合わせ」を参照)。

母艦となる乗り物自身のJSON定義に`runway`オブジェクト(1つのみ)、または`runways`配列(複数の甲板を持つ場合、任意個数)を追加すると、その乗り物の甲板上に滑走路が定義されます。

```json
"runway": {
  "width": 30.0,
  "center_x": 0.0,
  "height_y": 12.0,
  "start_z": -105.0,
  "end_z": 90.0
}
```

- 座標は全てこの母艦自身のエンティティ位置からの相対値で、母艦の現在の向き(ヨー)に合わせて回転します。`center_x`を中心に`width`ブロック幅、`start_z`〜`end_z`(順不同)の範囲、母艦位置から`height_y`ブロック上の高さに、矩形の滑走路が定義されます
- 実体としては、`CarrierRunwayPlatformEntity`(見えない床タイル)の集合が滑走路の範囲全体に敷き詰められ、艦載機の着陸装置・失速判定・当たり判定を、実際にブロックがそこにあるかのように扱います。タイルのサイズは`carrierRunwayExpectedWidth`(サーバー設定、既定30.0)から自動的に算出されます
- 滑走路が定義されていない乗り物は、この機能を一切使いません(通常の乗り物として動作)
- 複数の甲板・エレベーター等、独立した滑走路を複数持たせたい場合は`runways`配列を使います:
  ```json
  "runways": [
    { "width": 30.0, "center_x": 0.0, "height_y": 12.0, "start_z": -105.0, "end_z": 90.0 },
    { "width": 5.0, "center_x": 0.0, "height_y": 2.0, "start_z": -3.0, "end_z": 3.0, "hatch_offset_y": -8.0 }
  ]
  ```

#### ハッチ連動runway(任意項目)

`runway`/`runways`の各要素には、特定の`toggle_parts`の名前には一切依存しない、以下の
任意項目を追加できます。見た目のハッチアニメーションと連動させたい場合は、addonパック側で
両方の数値を揃えてください(自動連動はしません)。

- `hatch_gated`(bool、既定`false`): `true`の場合、このrunway(とその滑走路タイル)はハッチが開いている間だけ存在します。回転タイプのハッチ(揚陸艇の船首道板など、開閉の途中経過を追跡できないもの)向け。単純なon/off切り替えで、途中経過の考慮は一切ありません
- `hatch_offset_x`/`hatch_offset_y`/`hatch_offset_z`(double、既定`0.0`): 非ゼロの場合、ハッチが開くにつれてこのrunwayの実効位置がこの値ぶんまでイージングしながらオフセットされます(閉じると元の位置に戻ります)。上下・前後・左右の平行移動タイプのハッチ(空母のエレベーターなど)向け
- `hatch_move_speed`(double、既定`1.0`): 上記オフセットのイージング速度(進捗/秒)。`toggle_parts`の`"$hatch"`プレフィックス付きパーツと同じ倍率補正(設定speedの2倍で動作)が自動的にかかるため、見た目のハッチと同じ速度にしたい場合は、対応する`toggle_parts`の`speed`と同じ数値を指定してください

`hatch_gated`と`hatch_offset_*`は同時に指定することも技術的には可能です。

### 艦載機を発艦させる武器(`WeaponType.CARRIER`)

母艦に搭載する武器の設定ファイル(`.txt`)で武器種別を`CARRIER`にすると、その武器は実弾を発射する代わりに、艦載機(別の乗り物定義)をその場でスポーンさせ、設定されたルートを自動飛行させます。**この武器は滑走路(`runways`)の有無に関わらず動作します**(帰投した艦載機の回収は、下記`CarrierLandingToAmmoRadius`等による位置判定と、十分に減速しているかの速度判定で行われ、実際に滑走路タイルへ着地しているかどうかは問いません)。

主な設定項目:

- `CarrierAircraft`: 発艦させる艦載機の乗り物ファイル名
- `CarrierWaypoint`(繰り返し): 通常の哨戒/攻撃ルート(CAS武器と同じ書式:相対X,Y,Z,速度%,攻撃するか)
- `CarrierLaunchWaypoint`(繰り返し): 発艦直後に先行して飛ぶ、専用の離陸ルート。書式は`相対X,Y,Z,速度%,gear,bay,速度補正(km/h)`(gear/bay/速度補正の3列は省略可・`-`で「変更なし」)。**速度補正**は、そのウェイポイントに到達した瞬間、機体の水平速度の大きさをこの値(km/h)へ瞬時に上書きするカタパルト演出用の項目です(向きは維持、以降は通常の速度制御に任せます)。gear/bay列は着陸脚・武器倉の強制開閉トリガーですが、現状は0番目のウェイポイントでのみ実際に反映されます
- `CarrierLandingWaypoint`(繰り返し、1つ以上必須): 帰投時の着艦アプローチルート。`CarrierLaunchWaypoint`と同じ書式(速度補正列も指定できますが、着艦処理側では未使用です)。最後の1点が最終進入の基準点になります
- `CarrierLandingToAmmoRadius`(既定15.0): AddWeapon位置を中心とした半径。この範囲内にいる艦載機(有人・無人問わず)を弾薬1発分へ自動変換します。この回収ゾーンは常に有効で、滑走路の有無に関わらず機能します
- `CarrierRecoveryPoint`(繰り返し、任意): `相対X,Y,Z,半径`の書式で、上記のAddWeapon位置の回収ゾーンに加えて、追加の回収ゾーンを何箇所でも設定できます。座標はAddWeapon位置基準の相対値(母艦の向きに追従)。大型空母の複数の着艦スポットなどに利用できます

### 主な挙動

- **発艦**: 発射位置からスポーンし、`CarrierLaunchWaypoint`のルートを先に飛行してから、通常の`CarrierWaypoint`ルートへ合流します
- **座席の切り替え**: 発艦させたプレイヤーは、Alt+Y(既定)で発射母艦と発艦した艦載機の間で搭乗座席を切り替えられます
- **帰投・着艦**: `CarrierWaypoint`ルートの最終地点に到達すると、消滅せずに`CarrierLandingWaypoint`ルートを経由した自動着艦シーケンスへ移行します
- **弾薬への変換**: `CarrierLandingWaypoint`ルートを経由してAddWeapon位置付近まで戻ってきた艦載機、または`CarrierLandingToAmmoRadius`・`CarrierRecoveryPoint`のいずれかの回収ゾーン内にいる艦載機は、自動的にこの武器の弾薬(+1発)へ変換されます。この判定は位置・速度のみによるもので、実際に滑走路タイルへ着地しているかどうかは問いません(滑走路を定義していない母艦でも同じように機能します)

### 母艦への追従

滑走路上に存在するエンティティ(滑走路タイル自身・艦載機・その他の乗り物・プレイヤー等)は、母艦の移動・旋回に合わせて毎tick追従します。プレイヤーは`requestTeleport()`による差分ベースの位置更新、その他のエンティティは母艦の前tickからの移動量をそのまま加算する方式で追従します。無人の乗り物については、クライアント側で独自に物理演算(速度の再計算)を行わず、サーバー側で計算・同期された速度に基づいて位置を更新するだけにしてあります。これは、クライアント・サーバーそれぞれが独立に物理演算をやり直すと、値が僅かにズレて同期のたびに補正され、テレポートしたような見た目のカクつきになるためです。なお、カクつきそのものは完全には解決できておらず、僅かながら発生します(改善は保留中)。

## 燃料・補給・機体メニュー

- **燃料**: `max_fuel`(既定600)・`fuel_consumption`(既定0.5、1秒あたりの消費量、スロットルに応じた緩急カーブあり)を機体JSONで設定できます。燃料切れになるとスロットルが0に固定されます(操縦自体は引き続き可能)
- **機体メニュー(既定Kキー)**: 搭乗中にKキーを押すと開きます
  - **燃料補給**: 携行缶(`FuelCanItem`)をスロットにセットすると、携行缶内の燃料が機体へ供給されます
  - **弾薬補給**: 対応するアイテムを消費して、各武器の弾薬を補充できます
  - **カーゴ(機体インベントリ)**: `inventory_size`が設定された機体で利用できます。45マス(5行×9列、クリエイティブインベントリと同じ)を1ページとし、それを超えるサイズはページ送りで表示します(`VehicleMenuScreenHandler.PAGE_ROWS`)
- **携行缶と給油装置**: 鉄インゴットで携行缶(`FuelCanItem`)を作成できます。ピストン+かまど8個で給油装置を作成すると、燃料系アイテムを燃料へ変換して携行缶へ充填でき、携行缶から機体へ供給できます。クリエイティブ専用の無限燃料缶(`CreativeFuelCanItem`)も用意されています

## サウンドシステム

MCヘリの`Sound`/`SoundVolume`/`SoundPitch`/`SoundPitchRandom`/`SoundDelay`設定(機体・武器双方)に対応した独自のサウンド読み込み・再生システムを実装しています。

- **武器**: `WeaponDefinition`の`sound`(未指定時は`<武器名>_snd`)・`sound_volume`・`sound_pitch`・`sound_pitch_random`・`sound_delay_ticks`。射撃ごとに、その武器のワールド座標でワンショット再生されます。`sound_delay_ticks`は連射系武器向けの「実際に音を鳴らす間隔」で、発射レート(`cooldown_ticks`)とは別に管理されます
- **乗り物**: `VehicleDefinition`の`engine_sound`。エンジン音として継続的にループ再生され、スロットルに応じて音量・ピッチが変化します(アイドル〜フル)
- サウンドファイルは`assets/<namespace>/sound(s)/<名前>.ogg`(名前空間・フォルダ名`sound`/`sounds`のどちらも、全て検索対象)に配置します。`tudursvehiclemod-addons`のようなルースフォルダにも対応しています(`client.sound.AddonSoundLoader`がHUDシステムと同様の仕組みで直接スキャンします)
- 内部的にはMinecraft本体のサウンドシステム(`sounds.json`によるリソースパック登録)を経由せず、OGGファイルを直接デコードしてOpenALバッファへアップロードし、
  独自に再生を管理しています(ルースフォルダのファイルは`ResourceManager`から見えないため)
- 武器の発射音はサーバーからその乗り物を追跡している全プレイヤーへ専用パケットで通知し、各クライアントが個別に再生します

### 武器ステータス(実行時読み込み)

武器のダメージ・速度・発射間隔・重力・サウンド・弾丸モデルは、機体のJSONに焼き込まれるのではなく、`assets/<namespace>/weapons/<weapon_name>.txt`(MCヘリ形式そのまま)から**発射のたびに直接読み込まれます**(`asset.WeaponStatsLoader`)。これはHUDスクリプトと同様の仕組みで、`tudursvehiclemod-addons`のようなルースフォルダを直接スキャンします(`data/`配下のみ見える通常のサーバーリソースマネージャーでは`assets/`配下は見えないため)。

- バランス調整は`.txt`ファイルを直接編集し、`/reload`するだけで反映されます(再起動不要)
- 該当ファイルが見つからない場合は既定値(`WeaponStats.FALLBACK`)にフォールバックします
- `VehicleDefinition`の`weapons[]`には`weapon_name`(どの武器ファイルを見るか)のみが記録されます
- `DisplayName`(表示名)・`Round`(装弾数、0または未設定で無制限)・`ReloadTime`(リロード時間、tick単位)も読み取ります。装弾数のある武器は発射ごとに減り、0になると自動的にリロードを開始します(サーバー側で管理・同期)

### 武器の切り替え・発射キー

- 発射キーは既定で右クリック(`key.tudursvehiclemod.fire_weapon`)
- 武器切り替えキー(既定`R`、`key.tudursvehiclemod.weapon_switch`)で、搭乗している座席に割り当てられた武器の間で選択を切り替えます(他のキーバインドと同様、コントロール設定から変更可能です)
- 武器選択はクライアント側のみの概念です(サーバーは発射時に送られてきた武器インデックスを都度検証します)
- 同一の武器ファイルを参照する複数の`AddWeapon`は、MCヘリの仕様通り**単一の論理武器として1つにまとめられ**、発射位置(`offsets`)を発射のたびに設定順で巡回します(連装・多連装砲など)。個別に選択可能な別の武器としては扱いません

### HUDでの武器情報表示

`WPN_NAME`(武器名)・`WPN_AMMO`(現在の装弾数)・`WPN_RM_AMMO`(装弾数上限)・`reloading`(リロード中か)に対応しています。選択中の武器の情報が表示されます。

`WPN_NAME`のような文字列型の変数は、この式言語が本来数値(`double`)のみ対応のため、`%s`指定子で参照された際に「変数名そのものの識別子」と一致する場合のみ特別に文字列として解決される、専用の仕組みで実装しています(`HudExecutionContext.stringVariables`)。

### 武器タイプ・照準・爆発(MCヘリ挙動の再現)

MCヘリの`Type`ディレクティブに近い挙動を実装しています:

- **MachineGun1/MachineGun2**: 変換時に`MachineGun`として統合されます。
  照準追従(MachineGun2)か固定方向(MachineGun1)かは、**`Type`ではなく**`AddWeapon`の`MinYaw`/`MaxYaw`/`MinPitch`/`MaxPitch`が指定されているかどうかで決まります(指定があればプレイヤーの視点にその範囲内で追随、なければ`AddWeapon`自身のyaw/pitch(向き固定)を使用)。この判定は武器種別に関係なく共通の仕組みです。
- **Rocket**: MachineGunと同じ弾道(直進・重力は武器ファイル依存)。命中時の爆発・発火の扱いが主な違いです。
- **Bomb**: 発射すると機体自身の現在速度を引き継いだ状態で降下開始し、以降は武器ファイルの重力に従って落下します(固定初速は使用しません)。
- **爆発・発火**: 武器ファイルの`Explosion`(威力、0で爆発なし)・`ExplosionBlock`(0より大きければブロックを破壊)・`Flaming`(命中時に発火、`Explosion`が0の場合は無効)に対応しています。
- **Torpedo**: 機体姿勢が水平・低高度でなければ発射できません(低高度は直下の地面/水面までの距離で判定)。機体の速度を引き継いで開始し、重力に従って落下しますが、着水した瞬間から重力が無効になり、その時点の速度のまま直進を続けます(誘導はしません)。
- **ASMissile**: 発射した瞬間の、プレイヤーの視線が地面と交わる点(何も無ければ視線方向の最大探索距離の点)を目標として、徐々に向きを変えながら飛行します(誘導中は重力の影響を受けません)
- **AAMissile/ATMissile**: 発射キーを押した瞬間、照準(視線の中心付近、設定角度以内)にいる対象へ自動的にロックオンし、そのまま追尾します(対象が動けば毎ティック方向を再計算。対象が死亡・消滅した場合はその後直進を継続)。AAMissileは**現在空中にいる**対象のみ、ATMissileは**現在地上または水面上にいる**対象のみをロックオン可能です(機体の種別ではなく、対象の現在の物理的な状態で判定。地面から一定高度以上離れており水に触れていない場合は「空中」、水中に潜っている(目の位置が水面下)場合は「水中」として区別され、いずれもAAMissile/ATMissileではロックできません。水面上に浮いている・立っている状態は引き続き「地上」扱いでATMissileの対象になります)。ロック(`LockTime`で設定した時間、同一対象を照準内に維持)が完了するまでは発射キーを押しても発射されません。
- **Missile**(本プロジェクト独自、MCヘリには存在しないType名): AAMissile/ATMissileと同じロックオン・誘導・発射制限の挙動をしますが、空中/地上/水中の対象種別による絞り込みは一切行いません。
- **ASWeapon**(本プロジェクト独自、MCヘリには存在しないType名。`ASMissile`は既存のType名のため別名にしています): 対潜ミサイルです。AAMissile/ATMissileのようなロックオンではなく、ASMissileと同様に発射時の照準地点(水中の目標であれば、その水底付近の座標になります)を目標として誘導飛行します。目標までの距離が新規設定項目`DiveDistance`(既定10.0)ブロック以内になるまでは、目標の水平座標へ向けて水面のやや上を飛行し続け、その距離まで近づいた時点で目標そのものへ向けて潜航を開始します。着水した瞬間からは、魚雷(Torpedo)と全く同じ水中巡航システムに切り替わります(`AccelerationInWater`/`VelocityInWater`/`TargetDepth`をそのまま流用)。なお、弾頭分離など実際の対潜兵器が持つ複雑な多段階動作は実装していません。
- 誘導ミサイル共通のパラメータ(旋回速度・探索範囲・ロックオン角度)は現状固定値です。個別武器ファイルからの調整には対応していません
- ほか、MCヘリに存在する`MkRocket`/`Dispenser`/`Smoke`/`Dummy`/`TargetingPod`は実装済みです。`CAS`(近接航空支援、支援機を自動出撃させ攻撃させる武器タイプ)は、MCヘリと互換性のない別の独立した仕組み(`WeaponType.CAS`)として実装済みです。詳細は「無人機(UAV)・自律ドローン・近接航空支援(CAS)」セクションを参照してください

### 弾丸モデル

武器の`bullet_model`/`bullet_texture`/`bullet_scale`(MCヘリの`ModelBullet`から自動変換)が設定されている場合、投射物はバニラのアイテム表示ではなく、実際のOBJモデルで描画されます(未設定の場合は従来通りアイテム表示)。モデル/テクスチャ/スケールは`DataTracker`でサーバーからクライアントへ同期されます(サーバー側のみで設定した通常のJavaフィールドは、生成パケット経由のクライアント側エンティティには一切伝わらないため)。

## 航跡(Wake Trail)エフェクト

Ship・Submarine(浮上中)・水上機(`Float = true`の航空機)・Car(`SubmersibleDamageHeight`の範囲内で水に浸かっている場合)が水面上を移動する際、船尾・船首(左右に分岐する2系統)に、小さな四角いタイルの集まりを表示します。対象車種が水面を移動しているだけで自動的に発生し、追加の設定は不要です。

**実際のパーティクルシステムの代用**として、パーティクルではなく、車体モデル自体の描画に使われている仕組みを再利用した軽量なポリゴン描画を用いています(艦船の規模に関わらず自然に見えるようにするため)。

船首の左右2系統のタイルは、生成時点の船体の向きに対して**一定の角度**(実際の船舶が生み出すKelvin波の広がり角にならった考え方)で、船速に比例した速さで直線的に外側へ広がり、最大幅に達すると動作を停止して、消失するまでその場に留まります。速い船ほど短時間で最大幅に達し、遅い船はゆっくりと、あるいは表示時間切れになるまでに最大幅へ到達しないまま消えていくため、結果として遅い船の航跡は控えめな広がりにとどまります。船尾のタイルは、左右への移動はせず、記録された位置にそのまま留まります。

旋回中は、内側(旋回の中心側)のタイルについて、目標到達距離・広がる角度の両方が、その時点の旋回半径に応じて自動的に強まります(半径が小さいほど、より遠くまで、より急な角度で広がります)。これは、旋回中の内側の航跡が幾何学的に密度不足になりやすい(現実の船舶航跡でも同様の圧縮が起きる現象です)ことを補うための調整です。

生成位置は固定のオフセットではなく、各モデルの命中判定用メッシュを水面の高さでスライスし、実際のモデル形状から船首・船尾の交差点を動的に算出する方式のため、モデルごとの追加設定は不要です。

以下の2項目は乗り物設定ファイルで調整できます(いずれも省略可能):

- `wake_trail_spread_distance`:船首の航跡が最終的に到達する最大の広がり幅(ブロック単位)。**省略した場合、船体の命中判定用メッシュから水面での実際の船幅を自動計測し、その値を使用します**(小型艇から全長200ブロック以上の大型艦船まで、手動調整なしで自然にスケールするため)。自動計測した値が意図と異なる場合のみ、この項目で上書きしてください
- `wake_trail_duration_ticks`(既定`300`、15秒):航跡の各点(タイル)が消えるまでの表示時間(tick単位)。船首・船尾共通

## MCヘリ変換ツール(`tools/mcheli_convert.py`)

MCヘリ用アドオンパック(`.txt`設定+`.obj`モデル)を、このプロジェクトの`VehicleDefinition`JSON形式へ変換するツールです。

### 対応している主な機能

- 車両種別の自動判定(`AddRotor`/`AddCrawlerTrack`/`Float`+`Gravity`の強さから、ヘリ・車・船・潜水艦・水上機を判別)
- パーツファイル(`<機体名>_<パーツ名>.obj`)を本体の`.obj`へ統合し、`o`/`g`両方のグループ宣言として出力(一部の3Dツールは`g`しか認識しないため)
- **回転パーツ**(`spinning_parts`): `AddRotor`(ヘリのローター)/`AddBlade`(プロペラの実際の回転部分。`AddPartRotor`はVTOL機のローター筐体の傾きで、継続回転とは別物なので混同しないよう注意)/`AddPartRotation`。`RotorSpeed`(未指定時60)を「フルスロットル時の毎秒回転数」として解釈し、実際にスロットルへ連動して回転速度が変化します
- **トグルパーツ**(`toggle_parts`): ハッチ・キャノピー(`AddPartHatch`/`AddPartSlideHatch`/`AddPartCanopy`/`AddPartSlideCanopy`、Hキーで開閉)、ランディングギア(`AddPartLG`/`AddPartLGRev`/`AddPartSlideRotLG`、自動展開+手動格納)。同じ命名ファミリー内の複数のディレクティブ種別(例: `AddPartLG`と`AddPartSlideRotLG`の混在)は、ファイル内の実際の出現順序に基づいて連番を振るため、命名の衝突が起きません
- **Y座標のオフセット**: 艦艇・水上機以外は、OBJ座標の-0.30がMinecraftの地面と一致するため、変換時に+0.30を加算します(メッシュ・座席・武器・各種パーツのピボット座標すべてに適用、スライド式パーツの移動量には非適用)
- **座席位置の補正**: MCヘリとの見た目の差を埋めるための追加調整(-0.5)
- **CameraPosition**: 搭乗時のカメラ位置をMCヘリの`CameraPosition`/`AddGunnerSeat`のカメラ座標から反映(複数のCameraPositionを設定した場合、専用キーで切り替え可能。)
- **`OnGroundPitch`**: 大文字小文字を区別せず読み取ります(MCヘリ自体が大文字小文字を区別しないため、設定ファイル内の全項目名を小文字に正規化して比較しています)
- **HUD**: 機体設定ファイルの`HUD = <名前>`を読み取り、生成JSONの`"hud"`へ反映(未指定時は種別ごとの既定HUDを使用)。`assets/mcheli/hud/*.txt`・`assets/mcheli/textures/gui/*.png`を出力パックへ自動コピーし、コピーした**全ての**HUDファイルへ`manual_mode`/`stalling`/`gear_deployed`/`speed_kbh`の表示を自動追記します(各機体は自身のHUDまたは種別既定のHUDのいずれか1つしか使わないため、重複表示は実質的に問題になりません。再実行しても同一ファイルへの重複追記はされません)。追記したくない場合は手動で配置するなど行うか、スクリプトを編集してください。
- **サウンド**: 機体の`Sound = <名前>`(エンジン音)、武器の`Sound`/`SoundVolume`/`SoundPitch`/`SoundPitchRandom`/`SoundDelay`(発射音、`Sound`未指定時は`<武器名>_snd`)を読み取り、生成JSONへ反映。`assets/mcheli/sound/*.ogg`・`assets/mcheli/sounds/*.ogg`を出力パックへ自動コピーします
- **武器**: `AddWeapon`から座席・オフセット・`weapon_name`(武器ファイル名)をJSONへ反映するのみで、ダメージ・速度・発射間隔・重力・サウンド・弾丸モデルといった実際の数値は**焼き込みません**。`assets/mcheli/weapons/*.txt`を出力パックへコピーし、**実行時にそのファイルを直接読み込みます**(後述)。これにより、変換後にバランス調整したい場合は元の`.txt`ファイルを直接編集するだけで済み(`/reload`で反映)、再変換は不要です。ファイルが見つからない場合は既定値にフォールバックします(`WeaponStats.FALLBACK`)
- **弾丸モデル**: 武器の`ModelBullet = <名前>`を読み取り、`assets/mcheli/models/bullets/*.obj`・`assets/mcheli/textures/bullets/*.png`を
  `bullet_`接頭辞付きで`models/obj/`・`textures/vehicle/`へ再配置します(このプロジェクトのモデル/テクスチャ読み込みは固定パスのみ走査するため)

### 未対応の機能

- `AddRepellingHook`(ヘリコプターからモブを一定間隔で降ろすフック)

また、以下はMCヘリ本家の機能ですが、この MOD の設計上、**非互換**として意図的に対応していません:

- `AddRack`/`RideRack`(機体を機体に乗せる「ラック」機能)、および`ExclusionSeat`(座席/ラック間の排他制御) — このMODでは滑走路(`runways`)による機体の搭載・追随機能で代替しています
- `AddParticleSplash`/`EnableSeaSurfaceParticle`(水上移動時の水しぶき) —このMOD独自の航跡生成機能で代替しています
- 地形追従の傾き設定(`OnGroundPitchFactor`/`OnGroundRollFactor`/`SetWheelPos`) — 地形に応じた傾き機能自体は実装済みですが、MCヘリ本家とは異なる計算方式のため、これらの設定項目そのものに互換性はありません
- ガンナーモード(`EnableGunnerMode`)、および`ConcurrentGunnerMode` —このMODにはガンナーモード自体(パイロットが2番席の視点・武器を借りて操作する機能)が実装されていないため、非互換としています

※`CameraRotationSpeed`(戦車砲塔などのカメラ回転速度制限)は変換対応・代替機能ともに実装済みです。

※`DefaultFreelook`(搭乗直後からフリールック)は実装済みです。ただし、この MOD 独自の仕様として**通常のフリールックとは挙動が逆転**しています:`default_freelook`を有効にした機体は、既定でフリールック状態となり、解除キーを押している間だけ通常の固定視点に戻ります。

## バージョンについて(重要)

- Minecraft 1.21.11 は **Fabricが Yarn マッピングを更新する最後のバージョン**です
  (以降は Mojang 公式マッピングへの移行が推奨されています)。
- `gradle.properties` の `yarn_mappings` / `fabric_version` / `loader_version` は
  執筆時点の値です。ビルド前に https://fabricmc.net/develop/ で最新のビルド番号を確認してください。
